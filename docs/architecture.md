# Architecture

Sensei is a small state machine. A recognized mouse or menu action opens one task, further slow uses increment it, and the matching shortcut removes it. A later slow use opens it again. Each update is applied under a file lock and atomically writes `state.json`, so simultaneous shortcut and click processes cannot overwrite one another.

The durable state is only a lifetime shortcut total and unresolved tasks. It does not contain a stream of past actions. A bounded, sub-second guard prevents one physical shortcut from counting twice and prevents a shortcut-routed menu command from immediately reopening its task. The next coaching or diagnostic state update prunes expired guards.

Equivalent habits share one identity. Numbered, next, previous, former, and scroll workspace actions become `workspace-switching`. Positional `Bar panel N` actions become `bar-panels`. Bindings with an identical dispatcher and argument share a stable command-derived identity and the union of their current shortcuts. Directly named panels retain their own identity, so a positional panel shortcut cannot accidentally complete a named Bluetooth, Audio, or Network task.

The Quickshell panel renders the lifetime level plus open tasks and watches the compact state directory with native `FileView` notifications, so it does not poll or keep Python resident. Tasks are ordered by descending slow-use count, with the oldest task first when counts tie. The bounded list follows its keyboard cursor and supports arrows plus `h/j/k/l`. The required behavior itself is the completion action.

The level is derived directly from the aggregate shortcut total. Level 1 requires 10 uses; each next per-level requirement is `ceil(previous × 1.5)`. Shortcut callbacks arriving within 100ms are treated as one physical use without retaining the chord. The level card is read-only and does not alter coaching tasks.

The integration wraps every described non-mouse Hyprland shortcut with one pass-through dispatcher. It sends only the semantic action ID and title after dispatching the original action. It dynamically merges Omarchy's default and user menu definitions, resolves the same bindings as Super+K, and instruments every menu leaf with a unique high-confidence match. Matching is deterministic in descending confidence: identical commands first, then `omarchy-menu toggle|summon <route>` targets resolved through the menu's own IDs and aliases, then unique phrases and semantic token sets. Route resolution lets a leaf such as `style.theme` with alias `theme` match a shortcut that opens route `theme`, even though the leaf and shortcut use different shell commands.

Semantic fallbacks are accepted only when one menu item owns the identity and one binding matches it. Operation classes must also agree, so an installer, updater, remover, or setup action cannot be confused with an ordinary app or panel shortcut that shares its label. Ambiguous actions remain untouched, and the catalog reports each accepted match's confidence and evidence. There is no hardcoded action registry.

Slow actions enter the same identity graph from four event sources. The Sensei bar widget subscribes to Omarchy Shell's clickable-widget registry. It resolves the clicked button to its owning bar module while the semantic object is still available: exact shell-module target first, then unique manifest display name, then the live positional panel shortcut. Workspace widgets expose their workspace number directly. Only left clicks on the bar surface are eligible; clicks inside an open panel, clicks on Sensei itself, and widgets without a keyboard equivalent are ignored. One Sensei instance handles coaching across multi-monitor copies to prevent duplicate tasks.

The plugin service observes the existing Omarchy menu object's `activeMenu` identity and AppLibrary's launch serial. Menu routes are joined through their live IDs and aliases. App launches are joined through desktop ID, URL, executable, generic name, or the current default browser/editor/terminal role, in descending confidence. Private-browser, current-directory, compose, and other specialized variants cannot be completed by launching the ordinary app. A tie at the best score fails closed.

Window focus uses a compositor-local origin check. A non-consuming left-button press arms the observer; only a `window.active` transition while that button is down can be consumed by the matching non-consuming release. This prevents a keyboard focus change followed by a later click from being mislabeled. The application receives the original press and release unchanged, and ordinary clicks do not start Python. A recognized transition sends only the old and new window addresses; the short-lived helper reads current geometry and chooses the matching directional, monitor, or next-window binding from the live cache.

Generated menu wrappers preserve the complete merged item metadata, every shortcut alternative, and execute the original command byte-for-byte. A user-level path unit refreshes the catalog after menu or personal binding edits, and an Omarchy post-update hook refreshes it after upgrades.

The catalog refresh writes a small local cache of the same resolved bindings used by Omarchy's Super+K panel. If the compositor is temporarily unavailable, refresh uses the newest healthy Omarchy binding snapshot instead of replacing the catalog with the two static fallback records. Mouse and menu actions are matched against that cache without delaying their original UI action. `catalog --coverage --json` accounts for every binding as observed, matchable-but-unobserved, missing metadata, or keyboard-only, including source provenance and evidence.

Sensei does not capture raw keypresses or raw pointer motion. It sees described shortcut callbacks and a narrow set of semantic UI/compositor transitions. Broader coaching remains intentionally unavailable until Omarchy exposes an equally safe semantic event source.

Pre-2.0 installations are migrated under the same lock. Sensei folds `events.jsonl` once into the aggregate total and open tasks, atomically writes the new state, and only then deletes the old file.
